The article body is extracted from the full RSS entry when possible. If a feed contains only an excerpt, the workflow fetches the public page and extracts its readable content instead.

Headings, lists, links, code blocks, emphasis, and other basic structure survive the conversion, while navigation, forms, scripts, and page chrome are discarded.

The result is intentionally plain: typography that works on an e-ink screen, without ranking, summaries, engagement widgets, or algorithmic recommendations.

The pipeline

Five small stages, one finished artifact.

GitHub Actions supplies the clock and compute. Python handles feed parsing, extraction, canonicalization, EPUB creation, and delivery. The repository also holds the durable sent-state.

1

Collect

Read configured RSS and Atom feeds on a scheduled GitHub Actions run.

2

Extract

Prefer full feed content; fetch and clean the public article page when a feed is partial.

3

Build

Generate EPUB3 with a real cover image, contents page, native TOC, and one chapter per article.

4

Deliver

Email each generated EPUB through Gmail SMTP to Amazon's Send to Kindle service.

5

Remember

Persist delivered article IDs only after successful delivery so future runs do not resend them.

Why GitHub Actions?

The repository is the application.

For a small deterministic personal workflow, GitHub already provides the code host, scheduler, execution environment, secrets store, logs, artifact retention, version history, and deployment mechanism. There is very little infrastructure left to invent.

No VPS
No Docker host
No database service
No cron server
No paid automation platform
No mobile backend

Operations

Small enough to understand, careful enough to trust.

A personal automation still needs sane failure behavior. The system keeps delivery state explicit, secrets out of the repository, and test artifacts available when something needs inspection.

Reliability

  • Canonical-URL deduplication
  • Persistent sent-state in the repository
  • State updated only after successful Kindle delivery
  • No empty EPUB when a section has nothing new
  • Generated EPUBs retained as Actions artifacts for debugging
  • SMTP credentials stored only in GitHub Actions secrets

Built from an iPhone

The repository, feed configuration, workflow, EPUB format, delivery test, debugging, and deployment were all created and operated from an iPhone using ChatGPT and GitHub.

GitHub Actions became the remote runtime: the phone was the control surface, while GitHub supplied the filesystem, Python environment, scheduler, logs, and network access.
